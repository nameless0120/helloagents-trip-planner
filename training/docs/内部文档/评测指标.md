# Planner 评测指标

评测脚本位于 `training/scripts/eval/`，统一由 `training/scripts/run_pipeline.py --stage eval` 调度。评测记录必须带有结构化 `party`、`budget_constraint` 和 `PlannerContext`，这样人数和预算不需要从自由文本猜测。

## 主要通过条件

| 指标 | 含义 |
| --- | --- |
| `sft_hard_pass` | JSON、schema、日期、天气、行程结构、候选 grounding、酒店和基础预算约束都通过 |
| `sft_strict_hard_pass` | 在 `sft_hard_pass` 基础上，模型上报的预算分项也严格闭合 |
| `sft_budget_semantic_hard_pass` | 预算的天数、人数、档位关系正确 |
| `dpo_soft_pass` | 合法输出同时满足餐饮/景点多样性和预算偏好 |
| `planner_soft_pass` | 合法输出满足重算预算、餐饮尺度和多样性要求 |

## 关键诊断指标

- `json_extract_ok`、`schema_ok`：输出能否解析并符合 `TripPlan`。
- `day_dates_ok`、`weather_match`：日期和天气是否对应请求。
- `attraction_grounding_ok`、`hotel_grounding_ok`、`meal_grounding_ok`：候选事实是否来自上下文。
- `middle_hotel_ok`、`hotel_budget_covers_nights`：连续住宿和住宿预算是否完整。
- `budget_arithmetic_consistent`：模型上报的预算分项是否闭合。
- `recomputed_budget_user_constraint_ok`、`recomputed_budget_fit_ok`：按选中项目重算后是否符合用户预算和档位。
- `meal_diversity_ok`、`attraction_diversity_ok`、`meal_cost_scale_ok`：合法计划的软质量。

## 评测流程

```text
冻结 eval records
  -> 模型服务生成 TripPlan
  -> 规则解析和指标计算
  -> 按 standard / hard 和业务切片汇总
```

评测输出默认写入 `training/outputs/eval/` 下的本地 run 目录，不把模型生成明细和日志提交到仓库。详细命令见 [后训练实战教程](../教程/旅行助手后训练实战教程.md)。
